# Qwen3.5-122B-A10B (Ornith-1.5-122B-NVFP4) on one RTX 5090

Infernix runs [ornith-ai/Ornith-1.5-122B-NVFP4](https://huggingface.co/ornith-ai/Ornith-1.5-122B-NVFP4)
(revision `f049036f`), a `Qwen3_5MoeForCausalLM` at the Qwen3.5-122B-A10B geometry (48 layers,
H 3072, 256 experts top-8), on one 32 GB GPU. The routed experts (60.75 GiB) live in host RAM behind
a VRAM expert cache, as on [Qwen3.8-Flash-Next](qwen3_8-flash-next.md); everything else runs on the
GPU. Every weight except the speculative drafters is the checkpoint's own bits; the artifact can
include the MTP drafter (re-quantized) and the
[incoai/Ornith-1.5-122B-DFlash2](https://huggingface.co/incoai/Ornith-1.5-122B-DFlash2) drafter.

The model, its drafters, vision, `--reproducible` and `--lossless` run; the measurements and
remaining work are in the
[implementation plan](maintainer/qwen3_5-122b-offload-design.md#0-status-after-the-first-hardware-runs-2026-10-22).

## Requirements

- An RTX 5090 (or another `sm_120a` GPU with 32 GB).
- Host RAM: about 70 GiB free for the all-in-RAM mode (the experts pinned, plus the embedding, the
  vision tower and the prefix cache's host tier). With less, the RAM ledger keeps as many experts as
  fit and reads the rest from the artifact ([SSD expert tier](qwen3_8-flash-next.md#ssd-expert-tier));
  `--expert-ram-mib` and `--expert-pin-mib` set the split. Windows caps page-locked memory at its
  shared GPU memory (80 % of RAM).
- About 75 GB of disk for the artifact and 78 GB for the source checkpoint.

## Convert

Download both checkpoints (local snapshots), then convert with the converter's Python 3.11
environment ([weight conversion](weight-conversion.md)):

```bash
py -3.11 -m tools.convert --model <Ornith-1.5-122B-NVFP4 dir> --recipe qwen3_5_moe_nvfp4_modelopt \
  --components text,mtp,vision,dflash2 --source dflash2=<Ornith-1.5-122B-DFlash2 dir> --proposal \
  --resource sampling.json=tools/convert/sampling/ornith-1.5-122b.json \
  --name Ornith-1.5-122B-NVFP4 --out out/Ornith-1.5-122B-NVFP4-Infernix.infernix --device cpu --workers 4
py -3.11 -m tools.artifact.rename out/Ornith-1.5-122B-NVFP4-Infernix.infernix Ornith-1.5-122B-NVFP4-Infernix.infernix --numbered
```

`--proposal` adds the drafters' 131,072-row Q4 proposal head (214 MB, used with `--lm-head-draft`);
`sampling.json` makes the model card's recommended sampling (temperature 1.0, top-p 0.95, top-k 20,
min-p 0, presence penalty 1.5) the default in both thinking modes. The conversion took 16 minutes
on the i9-13900K without the proposal head. Check the result word for word against the
checkpoints:

```bash
py -3.11 -m tools.convert.verify_qwen3_5 --model <Ornith-1.5-122B-NVFP4 dir> \
  --artifact out/Ornith-1.5-122B-NVFP4-Infernix-00001-of-00003.infernix --dflash2 <DFlash2 dir>
```

It reports every expert record, tensor and FP8 input scale equal, and the drafters' tensors as
re-quantized.

### Ornith-1.5-122B-UNCENSORED-NVFP4

**Support is preliminary:** it runs and is verified, but optimisation is still in progress, so expect
its speeds to change.

[dealignai/Ornith-1.5-122B-UNCENSORED-NVFP4](https://huggingface.co/dealignai/Ornith-1.5-122B-UNCENSORED-NVFP4)
(revision `e6a1c178`, a refusal-removed export of the same model) converts with the same recipe. Its
routed experts, vision tower, embedding, router and norms have the same form; the rest differs:

- the attention, GDN and output projections are FP8 with an FP32 scale per row and no static
  activation scale (ModelOpt `FP8_PER_CHANNEL_PER_TOKEN`). They are stored exactly
  (`fp8_e4m3fn_row_f32`) and, as on the original, compute prefill with 8-bit activations and decode
  with 16-bit ones on the reproducible route, each activation column taking its own scale, as the
  checkpoint specifies;
- the shared experts are FP8 per row too (the original's are NVFP4): dense gate/up and down
  projections that run on their own stream beside the offloaded routed experts, with 16-bit
  activations;
- the head is FP8 per row (FP32 logits, 16-bit activations), and the MTP layer FP8 per row with
  block-FP8 routed experts, which the recipe reads at their exact values and re-quantizes as before;
- the bundled `dflash2/` drafter is byte-identical to incoai/Ornith-1.5-122B-DFlash2 but lacks its
  6 KB `mask_embedding.safetensors`: use Inco AI's repository (revision `9baefc1b`) as the drafter
  source;
- its card recommends temperature 0.6, top-p 0.95, top-k 20, min-p 0 and presence penalty 0 in both
  modes ([ornith-1.5-122b-uncensored.json](../tools/convert/sampling/ornith-1.5-122b-uncensored.json)).

```bash
py -3.11 -m tools.convert --model <Ornith-1.5-122B-UNCENSORED-NVFP4 dir> --recipe qwen3_5_moe_nvfp4_modelopt \
  --components text,mtp,vision,dflash2 --source dflash2=<Ornith-1.5-122B-DFlash2 dir> --proposal \
  --resource sampling.json=tools/convert/sampling/ornith-1.5-122b-uncensored.json \
  --name Ornith-1.5-122B-UNCENSORED-NVFP4 --out out/Ornith-1.5-122B-UNCENSORED-NVFP4-Infernix.infernix \
  --device cpu --workers 3
py -3.11 -m tools.artifact.rename out/Ornith-1.5-122B-UNCENSORED-NVFP4-Infernix.infernix \
  Ornith-1.5-122B-UNCENSORED-NVFP4-Infernix.infernix --numbered
py -3.11 -m tools.convert.verify_qwen3_5 --model <Ornith-1.5-122B-UNCENSORED-NVFP4 dir> \
  --artifact out/Ornith-1.5-122B-UNCENSORED-NVFP4-Infernix-00001-of-00003.infernix --dflash2 <DFlash2 dir>
```

The conversion took 13 minutes (three workers); the verification reports 12,288 expert records and
1,322 tensors equal and the 777 MTP and 55 DFlash2 tensors re-quantized. The artifact is 75.9 GB and
runs with the same options as the original.

Its speed, measured 2026-10-26 (RTX 5090, i9-13900K, one request) with INT8 KV, a fresh engine per run and three
texts (interleaved A/Bs, `tools/bench/abba.py`; ranges are across the texts):

| Workload | Speed |
|---|---|
| Decode, 1,280-token prompts, greedy: plain / `--spec mtp --draft-tokens auto` | 64-80 / 73-97 tok/s (MTP +18 % median, every pair) |
| The same at its card's sampling (temperature 0.6) | 64-80 / 68-97 tok/s (MTP +7.5 % median, every pair) |
| Prefill, 4K / 32K prompt | 1,700 / 4,530 tok/s |

Side by side with the original at these settings, prefill is the same (32K +1 %, 4K -0.4 %) and
decode differs by less than the run-to-run spread (+2.4 % median over two pairs, worst -5 %). The
per-token 8-bit prefill is 6.2 % faster at 32K than the same projections at 16-bit activations (no
difference at 4K, where the empty expert cache bounds prefill); the shared expert's own stream and
the compute stream time the same (decode +0.4 %, prefill 0.0 % for the compute stream, neither
resolved). MTP's drafter costs 3.4 % of prefill.

## Run

```bash
./build/apps/infernix out/Ornith-1.5-122B-NVFP4-Infernix-00001-of-00003.infernix \
  --prompt "Explain why the sky is blue." --max-context 8192 --max-new 256
```

- **Startup** takes 16-19 s: the weights load at about 5.5 GiB/s, the engine measures the PCIe link
  and the CPU expert team, and the expert cache takes the VRAM the rest leaves (about 4,450-4,850
  frames, 36-39 % of the experts). `--expert-state FILE` (default `<artifact>.expert-state`) restores
  the cache in about half a second at the next start.
- **Context memory**: only the first 32,768 tokens of KV are held at startup; longer contexts take
  their KV from the expert cache as they grow and give it back when they end, so a large
  `--max-context` costs expert-cache VRAM only while it is used.
- **Images**: `--vision` (the tower stays in RAM; the expert cache lends each encode window).
- **Serving**: `infernix-serve` takes the same artifact and options ([serving](serving.md)).
- `--reproducible` runs the bit-exact route; `--lossless` the correctly rounded one (eager rounds,
  about 5 tok/s).
- `--fast-path expert-a4-residual` (or `expert-a4-residual-3`, three terms) runs the experts' wide
  calls (prefill, more than eight columns an expert) on the FP4 tensor cores from two (three) NVFP4
  terms per activation row. It is not qualified for this model yet, so it never runs by default, and
  it is not request-invariant: an expert's result depends on its column count in the call.

## Performance (RTX 5090, one request, bf16 KV, default route)

| Measure | Result |
|---|---:|
| Plain decode (infernix_bench tg256 after a 512-token prompt, greedy) | 90-96 tok/s |
| Plain decode (the CLI's sampled request with the card's settings) | 74-78 tok/s |
| MTP, 2 drafts (`--spec mtp --draft-tokens 2`), the same sampled request | 78-81 tok/s |
| Prefill, 32K prompt | 6,500-6,530 tok/s |
| Prefill, 4K prompt | 1,740-1,750 tok/s |
| `--lossless` scoring (4,096-token windows) / decode | 106 / 4.7 tok/s |

Every figure is the default route with the model's own arithmetic. Decode speed depends on the text,
through the share of its experts already in VRAM (decode hit rate 74-80 %): it is bound by the bytes
of the missing experts, which the CPU computes from RAM (~53 GB/s) and the GPU reads over PCIe
(27.5 GB/s) at the same time.

`--expert-tail-skip R` is off by default. It skips a non-resident expert that every token of a decode
or verification round ranks R-th or lower, which changes the output and lowers quality; it is a
user-selected trade and no speed on this page uses it.

Speculative decoding works (`--spec mtp` or `--spec dflash2`). With MTP, each round verifies only the
drafts the drafter is confident enough of to pay for their experts (the rest are not computed).
`--spec mtp --draft-tokens auto` (recommended) drafts 2 that way: on three bench-corpus prompts (one
request, INT8 KV, 2026-10-25) it was 11-26 % faster than plain decode on greedy requests and -1 % to
+25 % on sampled ones (a geometric mean of 14 %), but about 6 % slower while two requests decode
together (each row's verify columns bring their own expert misses); the drafter takes about 1.3 GiB
from the expert cache. A fixed `--draft-tokens N` drafts up to N. DFlash2's per-round policy ties MTP
at one request (13.5 % faster than plain decode) and is 15.6 % slower than plain decode at two, so with
`--spec dflash2`, `--draft-tokens auto` decodes without a drafter (and does not load one, so the expert
cache keeps its VRAM). `--lm-head-draft` makes the drafters project through the 131,072-row proposal head
(artifacts converted with `--proposal`); verification keeps the full head.
